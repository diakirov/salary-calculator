# salary-calculator

Калькулятор змінної оплати для змінного графіка. Профілі, ставки, рівні,
надбавки й ролі доступу описуються конфігом — код не знає ні конкретних сум,
ні назв, і цей репозиторій їх не містить.

Друга версія інструменту. Перша була статичним SPA і померла від власної
архітектури: сторінка, що рахує гроші в браузері, віддає всі ставки кожному,
хто відкрив посилання — приватний репозиторій цього не рятує, бо опублікована
сторінка все одно публічна. Звідси й ребілд: та версія не могла бути
одночасно відкритою як код і закритою як дані, ця — може.

## Головне архітектурне рішення

**Браузер не отримує жодного числа зі ставок.** Фронтенд знає лише структуру
форми — назви полів, перелік профілів, місяці — і надсилає введені дані на
сервер. Сервер рахує й повертає готовий розклад нарахувань. Ставки живуть
в одному `config.json` у Docker-волюмі, якого в репозиторії немає і ніколи
не було.

За тим самим принципом винесено брендинг: логотип і зображення підтягуються
з того ж волюму після авторизації. У репозиторії — верстка й код, без асетів
і без назви організації.

## Конфіг замість коду

Що саме нараховується — цілком визначає конфіг. Рушій уміє:

- профілі з власною ставкою і набором етапів, у кожного — своя таблиця
  надбавок за рівень;
- надбавки з умовами виплати за рівнями;
- надбавку за вислугу: відсоток за рік від бази профілю, зі стелею;
- погодинні складові з множниками;
- довільні рядки доплат та утримань — оподатковувані або «вже чисті»,
  за прапорцем;
- норму годин за роками, місяцями й графіками роботи.

Приклад структури — увесь `config.example.json`. **Усі назви й числа в ньому
вигадані** й не описують нічиєї реальної схеми оплати; проєкт запускається
з коробки саме на ньому. Фрагмент (числа теж вигадані):

```jsonc
"profiles": {
  "role-a": {
    "name": "Профіль A",
    "baseSalary": 50000,
    "stages": [
      { "id": "main", "label": "Основний", "default": true,
        "zones": [ { "id": 1, "label": "Рівень 1", "premium": 8000 } ] }
    ]
  }
}
```

Кожен рядок нарахування округлюється до копійок окремо і лише потім
сумується. Рушій звірено з реальними розрахунками; ці тести та їхні фікстури
приватні, у публічному CI вони пропускаються, бо реальні суми — теж дані.

## Версії ставок

Ставки змінюються з певної дати, і старі місяці мають рахуватися по-старому.
Конфіг зберігає **список версій**, кожна діє з 1-го числа свого місяця:

- місяць рахується за версією, яка діяла саме тоді;
- майбутня версія створюється заздалегідь («застосувати з 01.09»);
- чинна версія незмінна — спроба відредагувати її повертає 409, бо інакше
  поїхали б заднім числом усі попередні розрахунки;
- користувач бачить смугу стану: «буде підвищення», «почне діяти з…»,
  «рахуємо за старими даними» — з ручним вибором версії.

Норма годин версіонується окремо, роком: додавання нового року не чіпає старі.

## Доступ

Один пароль = одна роль, без перемикача ролей в інтерфейсі. Перелік ролей
і те, які профілі кожна бачить, лежить у конфізі — це дані розгортання,
а не логіка. Пароль ролі зберігається як argon2id-хеш у змінній оточення
`AUTH_<РОЛЬ>_HASH`, сесія — підписаний httpOnly-cookie, на логін — rate-limit.

Захисту від того, хто вже увійшов, немає і бути не може: маючи пароль і
поділивши підсумок на години, константи свого профілю відновить будь-хто.
Інструмент рівно для цього й існує. Сенс авторизації в іншому — щоб цього
не міг зробити той, у кого пароля немає.

## Стек

- **сервер:** Node.js + Fastify, без БД — увесь стан у `config.json`
  з атомарним записом і бекапом кожної зміни;
- **веб:** React + Vite, стан форми та історія розрахунків у localStorage;
- **деплой:** Docker із жорсткими лімітами (256 МБ / 0.35 CPU / read-only fs) —
  на тому ж сервері живуть важливіші сервіси, і калькулятор не повинен мати
  можливості їм зашкодити.

## Запуск

```bash
mkdir -p config && cp config.example.json config/config.json
export SESSION_SECRET=$(openssl rand -hex 32)
export AUTH_ADMIN_HASH='...'          # docs/DEPLOY.md, розділ «Секрети»

cd server && npm i && PORT=8792 npm run dev   # API (vite-proxy дивиться на :8792)
cd web && npm i && npm run dev        # Vite dev-сервер із proxy на API
cd server && npm test                 # рушій і версії
```

Прод — `docs/DEPLOY.md`.

## Що свідомо не зроблено

- **Спільного «двигуна форм» немає.** Профілі описуються даними, але UI один
  і без мета-магії: генератор інтерфейсу з конфігу коштував би дорожче,
  ніж усе, що він мав би зекономити.
- **БД немає.** Один JSON із версіями покриває задачу; база стала б
  найважчою частиною системи заради нічого.
